# Sprint 2026-05 — May 2026

## Sprint goal

Three parallel tracks: (1) Fix Facebook post permalink extraction quality. (2) Add full in-reader content editing, expanded toolbar, and PDF merge. (3) Refactor `reader.js` into ES modules, add a ChatGPT extractor, right-click context menu, floater re-injection guard, and fix reader auth button first-load rendering.

---

## Initiatives delivered

### 1. Facebook post permalink extraction

**Problem:** Facebook post permalink URLs (`facebook.com/user/posts/postid`) produced polluted reader views — repeated "Facebook" navigation text, CSS-scrambled date characters, and unrelated feed content. In logged-in state, Readability extracted the whole news feed instead of the post.

**What was built:**

- `isFacebookPostPermalink()` — detects `facebook.com` URLs with `/posts/`, `/permalink.php`, or `/photos/` paths
- `FB_POST_PERMALINK_SELECTORS` — ordered selector list: `[data-pagelet="PermalinkPage"]`, `[data-pagelet*="Permalink"]`; intentionally excludes `[role="main"]` (contains full news feed in logged-in state)
- `extractFacebookPermalink()` — **Priority 0b** in `extractArticle()`: fires before dialog detection and Readability; returns `null` in logged-in state (no permalink pagelet found) so Priority 1 dialog detection handles the post modal as before
- `pruneFacebookNode(clone)` — extends standard noise removal with FB-specific removals: pagelets `ColumnRight`, `RightRail`, `Stories`, `Composer`, `Suggested`; ARIA roles `complementary`, `navigation`, `banner`; plus standard noise elements. Operates on a clone, never mutates live DOM.
- `removeScrambledDates(clone)` — removes CSS-obfuscated timestamp containers using a structural heuristic: ≥10 direct children of which ≥65% have 1-character visible text content
- `cleanFacebookTitle(rawTitle)` — strips `(N+)` notification count prefix and `| Facebook` suffix from document title; applied only in the permalink path

**Key constraints:**
- `data-pagelet` attributes are the only stable structural hook on Facebook; class names are dynamically generated
- The 65% single-character threshold in `removeScrambledDates()` avoids false positives on legitimate content with short words

### 2. Full reader edit mode

**What was built:**

- `#editBtn` — pastel yellow (`#fef9c3`) button in the reader header secondary row
- `#editToolbar` — fixed bar below the main header when `body.edit-mode` is active, containing:
  - Bold / Italic / Underline (toggle via `document.execCommand`)
  - Font color (`<input type="color">`)
  - Font size (select 12–36 px; uses `fontSize('7')` marker + inline-style conversion to bypass execCommand's 1–7 scale)
  - Align Left / Center / Right
  - Bullet list (unordered) and Numbered list (ordered)
  - Horizontal rule insert
  - Insert Note callout block
  - Insert Image (FileReader → base64 data URL → `execCommand('insertHTML')`)
  - Insert / Edit Link (link popover)
  - Save and Cancel
- `enterEditMode()` — makes `#articleTitle`, `#articleByline`, `#articleBody` all `contenteditable="true"`; snapshots all three for Cancel revert; strips `contenteditable="false"` and `user-select: none` / `pointer-events: none` from extracted child nodes; uses `requestAnimationFrame + { preventScroll: true }` for reliable cursor placement
- `exitEditMode(save)` — on Save: persists `bodyEl.innerHTML` to `currentArticle.content` in `chrome.storage.session`; on Cancel: restores snapshots; always calls `closeLinkPopover()`
- `applyFontSize(px)` — uses `fontSize('7')` as a marker, converts all `<font size="7">` to `style.fontSize` in px
- `insertHorizontalRule()` — `execCommand('insertHTML')` with `<hr><p><br></p>` so cursor lands after the rule
- `updateToolbarState()` — 30 ms debounced on `selectionchange`; reflects B/I/U active state via `document.queryCommandState()`
- Keydown guard: suppresses Flash It and font shortcuts while `isEditMode` is true (except Escape)
- `mousedown → preventDefault()` on `#editToolbar` prevents toolbar button clicks from collapsing the active text selection; carve-outs exist for `<select>`, color `<input>`, and Save/Cancel

**Key constraint:** `document.execCommand()` is deprecated per web spec but remains the only viable in-browser formatting API without an external library; it works correctly in Chrome extension contexts.

### 4. Link popover bug fix + `https://` pre-fill

**Problem:** Clicking Apply in the link popover did nothing. Root cause: `applyLink()` called `closeLinkPopover()` first, which set `savedLinkRange = null`, then checked `if (!savedLinkRange)` — always returning early.

**What was built:**

- `applyLink()` — captures `const range = savedLinkRange` before calling `closeLinkPopover()`; treats bare `'https://'` as a no-op; applies `target="_blank"` and `rel="noopener"` to all created links
- `unlinkSelection()` — same fix: captures `const range = savedLinkRange` before close
- `openLinkPopover()` — URL input pre-filled with `'https://'`; pre-fills existing `href` when cursor is inside an `<a>` tag

### 5. Sidepanel "Merge & Create PDF"

**What was built:**

- `sidepanel/pdf-build.js` (new module) — exports `handleMergePDF()`:
  - Fetches all saved articles via `getAllArticles()`
  - Builds a styled HTML document with cover page, table of contents, and per-article sections with page-break CSS
  - Opens a blob URL in a new tab via `window.open()`; the new tab auto-invokes `window.print()` on load
  - Blob URL revoked after 90 seconds
- `#mergePdfBtn` added to `sidepanel.html` footer (`.btn-pdf` class, red `#c0392b`)
- Enable/disable wired into `reading-list-render.js` alongside EPUB and X4 buttons
- Print HTML: Georgia serif, cover page, TOC with anchor links, per-article page breaks, note-block and `hr.note-sep` styling, `@media print` rules

**Key constraint:** No third-party PDF library is bundled; the blob HTML approach produces full-fidelity output (images, fonts, colors) that text-extraction libraries cannot match. Button label is "Merge & Create PDF" — user completes the save via Chrome's print dialog.

### 6. Reader ES-module refactor

**Problem:** `reader.js` had grown to ~2,400 lines — article rendering, preferences, auth, edit mode, TTS, Flash It, and EPUB all in one file. Increasingly hard to navigate and safe to change.

**What was built:**

- `reader.js` reduced to ~160-line ES-module entry point
- Eight new modules under `reader/`:
  - `reader/state.js` — shared mutable state + module-level constants
  - `reader/article.js` — article load, sanitisation, lazy image loading, reading-list save (`handleAddToReadingList`, `autoSaveToReadingList`), notification toast
  - `reader/preferences.js` — theme, font size, width, progress bar, pref load/save
  - `reader/auth.js` — reader header auth UI (guest/avatar), sign-in/out handlers, dropdown open/close, `authUpdated` message handler
  - `reader/edit-mode.js` — all edit-mode logic: `enterEditMode`, `exitEditMode`, `execFormatCmd`, `applyFontSize`, `insertNoteBlock`, `insertHorizontalRule`, `insertImageAtCursor`, link popover, `updateToolbarState`
  - `reader/tts.js` — TTS playback, voice selection, sentence chunking, `sendArticleToWebapp`
  - `reader/flash-it.js` — Flash It speed reading (start, pause, resume, restart, stop, mode change, speed update)
  - `reader/epub.js` — single-article EPUB / HTML download / email-EPUB modal
- `reader.html` now loads `reader.js` with `type="module"` — same pattern as `sidepanel.html`
- `chrome.runtime.onMessage` listener remains in `reader.js` since it wires multiple modules
- `<base href>` injection moved to the top of `DOMContentLoaded` in `reader.js`, before `loadArticle()` is called

### 7. ChatGPT conversation extractor

**Problem:** ChatGPT pages (`chatgpt.com`) rendered blank or garbled in reader view — React layout uses obfuscated class names, `position:absolute` everywhere, and no semantic `<article>` tags.

**What was built:**

- `isChatGPT()` — detects `chatgpt.com` and `chat.openai.com` by hostname (strips `www.` prefix)
- `extractChatGPT()` — **Priority 0a** in `extractArticle()` (before FB permalink, dialog, and Readability):
  - Queries all `[data-message-author-role]` elements (user / assistant turns)
  - De-duplicates nested role elements (keeps only top-level turns)
  - For each turn: clones element, strips action buttons / toolbars / copy overlays / SVG icons, applies `makeUrlsAbsolute()`, resets all `position:absolute/fixed/sticky` inline styles to `relative`, removes transforms and z-index, normalises image sizes, styles code blocks
  - Wraps each turn in `<section class="chat-turn chat-turn--user/assistant">` with `<h3>` label ("You" / "ChatGPT")
  - Cleans title by stripping `" - ChatGPT"` suffix; returns `extractionMode: 'chatgpt'`

**Key constraint:** `[data-message-author-role]` is a stable semantic hook (verified May 2026); class names are obfuscated and change with deployments. The inline style reset on `position:absolute/fixed/sticky` is critical — without it, divs and images float outside normal flow in the reader's single-column layout.

### 9. Floater ping-based re-injection guard

**Problem:** The re-enable path unconditionally injected `selection.js` into all open tabs, creating duplicate launcher instances in tabs where the script was already running.

**What was built:**

- Before injecting on re-enable, `background.js` sends `{ action: 'ping' }` to the tab
- `selection.js` responds `{ alive: true }` synchronously if already running
- Success → skip injection; failure (no listener) → inject via `.catch()` branch
- This is idempotent: two rapid re-enable calls produce at most one injection

### 11. Reader auth button first-load rendering fix

**Problem:** On first load of the reader view, the auth button showed a broken image placeholder instead of the SVG guest icon. After signing in and out, the icon appeared correctly.

**Root cause:** `reader.css` sets `display: flex` on `.icon-btn`, making `#readerAuthBtn` a flex container. The old `.auth-guest-icon` used `align-self: stretch` to fill the button — this silently fails on first paint in Chrome's extension page renderer. The sign-in/sign-out cycle triggered a CSS class toggle (`.signed-in`) that accidentally corrected the rendering. The sidepanel auth button had no issue because `sidepanel.css` does NOT set `display: flex` on `.icon-btn`.

**What was built:**

- `reader.css` — `#readerAuthBtn` given `position: relative`
- `#readerAuthBtn .auth-guest-icon` changed from `width: 100%; align-self: stretch; display: flex` to `position: absolute; inset: 0; display: flex; align-items: center; justify-content: center`
- `#readerAuthBtn .auth-avatar` updated to `position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover`
- `reader/auth.js` — `onerror` handler on avatar `<img>`: if stored profile picture URL fails to load (e.g., expired Google CDN URL), reverts button to guest-icon state

**Key constraint:** `position: absolute; inset: 0` is display-type-agnostic — fills the parent `position: relative` container regardless of whether the parent is flex, block, or inline-block.

## Key risks

- Facebook's `data-pagelet` attributes are the only stable structural hook; could change in future FB platform updates
- `document.execCommand()` is deprecated per web spec; monitor Chrome platform announcements for removal timelines
- `[data-message-author-role]` is a stable ChatGPT DOM hook as of May 2026 but is an internal React prop — OpenAI could remove or rename it
- The `position: absolute; inset: 0` fix in `reader.css` relies on `#readerAuthBtn` having `position: relative` — future refactors must preserve this positioning context
- Apple Books and other EPUB readers vary in which CSS properties they honor; the gradient background workaround for note blocks may need updating if Apple Books changes its override behavior
